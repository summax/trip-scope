# 范围裁剪与实现基线记录(2026-11-17)

> 本文是**成品实现的需求基线**:V8.1 冻结需求(`requirements-v8.md`,基线 `dc46fe0`)+ 本轮人工裁决的裁剪与取舍。需求/模型文档的正式 v8.2/v1.4 修订留待产品验收后;实现以本文为准。

## 一、功能域裁剪(用户裁决,2026-11-17)

以下五个功能域**整体移除**,成品中不实现,记账一律填实付净额:

1. **退款**全部机制:退款记录、关联方式(单笔/预算行)、退款上限、超额退款校验、补偿收入
2. **押金退回**:押金三去向的"退回"去向
3. **押金支付类型 + 押金转消费**:押金不再是支付类型;押金转消费(E24 份额/E25b)随之移除;遇到押金按普通支出(其他/预付款)记一笔
4. **返利(Rebate)**:返利/返现事后到账直接修改对应支付的实付金额(金额调整+审计保留)
5. **优惠结构(Adjustment)**:候选报价不拆优惠项;附加费(Surcharge)保留(默认裁决,未明确反对)

**连带失效/简化(机械推论,实现侧执行)**:
- 支付类型收缩为流出类四种:全款/尾款/预付款/其他;三分类映射、冲减类、跨分类纠错(DM-10)与"常规调整跨分类禁令"失去对象,不再实现
- 三层历史快照塌缩:清理时仅在支付上附**一层**行级快照(版本号/行名/行金额/清理时点支付金额),E25b/E25c 与 paymentTypeAtCleanup 不再需要
- 押金守恒(DM-05)、退款上限(BC-24/I-20d)、Q2 押金开关(displayConfig)消解
- v1.3 落文的 R6(纠错机制采纳)按上述收缩执行;R7(冲减类归属)随冲减类移除**整体作废**
- 报价侧价格 = 成人基准价 + 票档覆盖(比例/绝对额)+ 附加费;无优惠拆项

## 三、保留并实现的核心语义(摘要)

- 旅行:名称/日期范围/旅行者(挂票档)/票档(成人 100%,其余按比例或绝对额覆盖)
- 消费对象:交通区段/住宿单/房间项/自由费用,对象级共享设置(参与人,空=全体)
- 候选:交通(按人计价)/房间(按间每晚)/整段套餐(一口价),附加费,报价有效期
- 组合:选择集 + 住宿计价模式(DM-01:模式是组合层持久状态,"套餐已选但未生效"可表达)
- 方案:存档=复制组合;加载=整体替换+确认;对比=组合与全部方案同屏,候选已变化 → 差额提示
- 预算:版本链(confirm 首发 / refresh 按现价),logicalLineId 传播,版本对比(改额/新增/不再包含),清理+行级快照
- 支付:实付金额(整数分),四种类型,归属三态(行/预算外/待归位),归属操作与调整全部留痕,行级多付警告
- 汇总:预算侧(当前版本行)与记账侧(支付)分列;按人(分摊)、按日、按类;已付 vs 预算差额;范围外金额单列 R
- 分摊:交通/费用按参与人均分(最大余数法);住宿按晚分摊给当晚占用房间的人;无分配则按参与人按晚均分
