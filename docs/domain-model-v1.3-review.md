## 3. §6.11 加载建模自查

- **设计完备性**：整体替换语义（无合并）、显式确认前置、候选/预算/支付零改动、审计与撤销边界（组合层操作不产生 E21）、悬空候选走 §6.10 既有规则、加载后的预算吸收路径（显式刷新，策略乙）均已定义；边界与"保存方案 = 整体复制"对称。
- **一致性**：加载不触碰 E21 审计域（§10.4 已补）；首次确认路径不变（§6.1：从方案快照）；已定稿旅行加载后吸收进预算走刷新（来源=当前组合 + 快照必生成），与 R1 自洽。
- **开放点**：loadedFromPlanId/loadedAt 仅登记为可选展示元数据【技术建议】，不参与计算；§6.11 无冻结 AC（裁决扩项），实现期须补"整体替换确认弹层 / 方案零改动 / 支付零改动"三类断言——已写入 §6.11 验收行。

## 4. R7 裁决解读的确认与残余风险

- 用户自由输入"全方案不在考虑退款押金的问题"由本轮解读为**选项一（不适用/恒空）**：冲减类不携带归属语义、作用对象仅由 refundTarget 表达。正文 §4.11 裁决段已注明解读依据与历史论证保留位置。
- **残余风险**：若该解读与用户本意不符（例如本意是"退款/押金问题整体搁置"），R7 需复议。本报告与 §4.11 均已显式标注"按用户原话解读"，供终审复核。

## 5. R1 策略乙的连带影响推演

- 刷新 → 新版本行 = 刷新时点组合现状；未存档临时改动随之进入正式预算（设计如此），**实现期义务：刷新确认弹层文案必须明示"按当前组合刷新"**（C11 张力的兜底）——已写入 §4.10 定案段与 §15 P2-1。
- logicalLineId 传播（情况 A/B）、支付不自动转移、三层快照规则在策略乙下原分析成立；DM-09 的"禁止静默继承首次确认来源"禁令保留。
- sourceSnapshot 每次必生成不引入新校验：结构（selections+quantityDecision+stayModes）与 §4.9 组合层定义同构，无价格字段。

## 6. R4 份额改额守恒校验推演

- 押金 500 → 份额 A 200 → 调整为 300：Σ退回 0 + Σ转消费 300 ≤ 500，通过；审计链 = 原始份额审计 + 金额调整审计，撤销走补偿链。
- 拒绝场景：份额 A 200→450 且份额 B 100 存在 → Σ转消费 550 > 500，**拒绝保存**（先拒绝后写入）。
- E25b 快照不回写（快照一经生成不可改写，共同规则）；"押金→流出"纠错仍被"份额存在"拒绝（R4 不改变纠错前置）。
