## 0. 本轮修正

前几轮我犯了同一类错误:**把实现问题当需求问题问**。

- 问过"网格布局选哪种""要不要支持项目→类型两层""能不能进入设计阶段"

## 1. 这个工具要解决什么问题

一次家庭旅行,在定下来之前,有大量**可替换的选择**:

- 哪天出发(早一天机票便宜 200,但多一晚房费)
- 从哪个城市进出(合肥直飞贵,安庆出发便宜但要折腾)
- 坐飞机还是高铁(高铁慢 4 小时,省 300)
- 住哪(酒店 A 每晚 200 但远,酒店 B 套餐 3 晚 999 但含早)
- 孩子算不算钱(机票儿童半价,酒店加床另算,景点儿童票)

这些选择**互相牵连**:早一天走,机票便宜但住宿多一晚;换酒店省 200,但打车费多 80。
真正的决策不是"机票选哪个",而是**"整套组合下来一共多少钱,哪套最划算"**。

现状是这些信息散在携程、飞猪、12306、小红书攻略、飞书表格里,**人脑算不动组合**。
所以要么凭感觉拍板,要么在 Excel 里手工搭一张表,改一个数就要重算一片。

**TripScope 要做的**:把这些候选价格收进一处,让我能自由组合、随时看总额变化、横向比较几套方案,并且这个文件能双击打开、离线用、发给家人。

## 2. 使用阶段与各阶段需要的能力

| 阶段 | 我在干什么 | 需要工具支持什么 |
|---|---|---|
| 规划期(出发前 1–3 月) | 到处查价,把看到的记下来 | 快速录入候选价格;同一航班不同日期不同价;同一酒店不同房型不同价 |
| 定稿期 | 反复组合,比哪套划算 | 逐天/逐类别挑选;随时换一个看总额变化;保存几套组合横向比 |
| 决策后 | 定下来,准备出发 | 选定一套成为正式预算;生成行程简表 |
| 出行中 | 花钱,记账 | 快速记一笔实付;随时看待付多少 |
| 归来 | 复盘 | 预算 vs 实付对比;返利到账后净支出;按天/按类/按人看 |
| 分享 | 给家人看、留档 | 转发文件本身;导出文字行程单发微信;打印/PDF |

## 3. 需求条目

每条写:**要能做什么** / **为什么需要** / **验收怎么算过**。

### R1 管理候选价格

**要能做什么**

- 把查到的价格录进来,一条候选 = 某个东西 + 某天(或某几天)+ 一个价
- 同一交通/住宿,不同日期不同价,可以一次录多条(机票价格随日期变是常态)
- 同一家酒店的不同房型、不同渠道的不同价,分别录
- 一条候选可覆盖多天(3 晚套餐、一周餐饮),不是只能一天
- 候选可带说明性备注(如"含双早、可免费取消")
- 金钱性质的优惠(返利、立减、赠送抵扣)**单独记录且可计算**,不能只写成备注文字
- 录入成本必须可接受:几十个格子不允许只能一个个手点(支持的录入方式见 §10)

**为什么需要**
候选是整个工具唯一的原料。录入如果痛苦,工具就不会被使用。

**验收**
- 能把一张现有 Excel 备选表的内容录进来,且不需要重复劳动
- 一条"合肥~海口"能同时录 9/29=700、9/30=700、10/1=900
- "3 晚套餐 999"能作为一条录进去,并且占用 3 天
- 返利"连住 3 晚返 300"输入后,总额确实少了 300(不是只在备注里写一句)

### R2 组合选择

**要能做什么**

- 逐天、逐类别挑选:某天住哪、某天怎么走、某天玩什么
- 一天可以有多笔:交通一天可多段(飞机 + 打车 + 轮渡),餐饮一天多笔,门票一天多个
- 住宿一晚一组;同一家酒店的不同房型可以同时要(1 标准间 + 1 家庭房),不同酒店不能同时占同一晚
- 套餐必须整段使用,系统要知道哪些晚已被占
- **所有候选要能同时看见并直接比较**,不能只能一个个点开看
- 每家酒店的不同房型要能并排看出差价
- 选择可随时反悔、可反复替换
- 空白是合法状态:某天没考虑住宿/交通,不是错误,也不等于免费

**为什么需要**
"一眼看出优劣"的前提是所有候选同时可见。逐个点开看,永远得不到全局感。

**验收**
- 同一天能同时有 3 段交通,合计正确
- 同一酒店两个房型并排显示,能直接看出每晚差 30
- 一晚同时选两家不同酒店 → 明确提示冲突,不静默接受
- 一晚同时选同一家的标准间 + 家庭房 → 正常,合计相加
- 选了 3 晚套餐后,再往其中一晚加单夜房 → 提示该晚已被占用
- 某天什么都不填 → 不报错、不计费、可正常保存

### R3 费用计算

**要能做什么**

- 大人 / 小孩 / 老人不同价,按票档区分;票价可按成人价的比例算(儿童 = 五折),也可直接填绝对额
- 支持多种计价口径:按人、按间夜、按天、按人按天、整段套餐一口价、单纯一口价
- 住宿要考虑加床费、儿童早餐费
- 返利/优惠按"一次性减 / 每晚减 / 每人减"正确展开
- 没查到价的项目要**显式标出来**,不能当 0 混进合计
- 金额不能有分位误差(3 人分 100 元,三份加起来必须正好 100)

**为什么需要**
家庭出游的坑几乎都在"大人小孩不同价"和"人均摊"上。算错一分钱,整张表就不可信。

**验收**
- 4 人(3 成人 1 儿童)→ 机票儿童价按 5 折正确;改成固定 800 也正确
- 改人数后,所有按人计价的项同步变化
- 有 1 项没填价 → 汇总显示"含 1 项待估",该组合不被判为最便宜
- 3 人分 100 元 → 34+33+33,合计严格 100

### R4 汇总

**要能做什么**

- **每天花多少**:逐日小计,能看出哪天最贵
- **每类花多少**:住宿/交通/餐饮/门票各自合计与占比
- **总共多少**:总费用、人均、日均
- **每个人多少**:各人应付(票档直接归属 + 公共费用均摊)
- **两个方向要对得上**:按天加起来 === 按类加起来 === 总费用

**为什么需要**
最后两个方向互相校验,是发现"算错了"的唯一手段 —— 格子多到一定程度,人无法手算验证。

**验收**
- 10 天行程,日小计逐日相加严格等于总费用
- 分类小计相加严格等于总费用
- 各人应付相加严格等于总费用
- 日均 = 总费用 / 天数,人均 = 总费用 / 人数

### R5 方案对比

**要能做什么**

- 把当前这套组合存成一个具名方案,可存多套,数量不设上限
- 横向比较:每套方案各类别花多少、总费用差多少、贵/便宜在哪一类
- 最低价那套要明显标出
- 含未定价项或住宿冲突的方案,**不能被判为最便宜**(避免漏填反而赢)
- 天数不同的方案,要能公平比较(人均、日均)
- 除了钱,还要能看到:航班/车次时刻(有没有早班、深夜到)、儿童友好程度(含早、婴儿床、泳池、亲子房)
- 能随时回到某套方案继续改

**为什么需要**
决策就是"选哪套"。没有横向对比,选择只能靠感觉。

**验收**
- 存 3 套方案后可横向看到各类别金额与总价差额
- 最低价高亮;含未定价项的那套带警示且不参与"最低"评比
- 一套 7 天 2 万、一套 6 天 1.9 万 → 能看出总价谁低、日均谁低
- 能对某套方案说"比最便宜的贵 1240,主要贵在住宿 900"

### R6 记账与复盘

**要能做什么**

- 选定一套方案后,成为正式预算
- 出行中随手记一笔实付(金额 + 类别 + 日期 + 备注)
- 显示待付多少(预算 − 已付)
- 返利到账后可登记,净支出 = 实付 − 已收返利
- 归来后看预算 vs 实付的差额,按天/按类/按人

**为什么需要**
计划工具的价值一半在"出发前算准",另一半在"回来知道准不准"。

**验收**
- 记一笔实付后,待付与净支出正确更新
- 预算 5000、实付 4800、返利 200 → 净支出 4600,显示省了 400

### R7 输出与分享

**要能做什么**

- 整个旅行文件本身可转发(微信/邮件/U盘),对方双击就能看
- 导出纯文字行程单(按天:日期、住哪、怎么走、玩什么、当天花费),可直接粘贴到微信
- 打印友好视图 / 另存为 PDF(去掉按钮控件,分页合理)
- 导出方案对比为文字表格
- 长图导出(P2,优先级低于以上)

**为什么需要**
家庭出游的信息必须能让不装软件的人看到。

**验收**
- 文字行程单粘进微信后,分段与金额正确
- 打印预览下没有按钮和输入框,一页放得下 1–2 天
- 对比表文字版可直接发群

### R8 数据安全

**要能做什么**

- 单文件、双击打开、完全离线、无需账号、无网络请求
- **改日期范围不丢任何已填数据**
- 编辑内容有本地兜底,浏览器崩溃后可恢复
- 文件被多份修改后,合并/覆盖前必须让我知情并选择,不能静默覆盖
- 工具升级后,老旅行文件能打开并自动迁移
- 遇到不认识的新版本数据 → 只读,至少能导出,不破坏原文件

**为什么需要**
这是"一份文件就是全部家当"的模型,数据丢了没有服务端可找回。

**验收**
- 把 10 天缩到 6 天,再改回 10 天 → 原有数据全部还在
- 关闭页面重开 → 未保存的编辑可恢复
- 用两个副本分别改后写回 → 提示冲突,让我选
- 老版本文件打开 → 自动迁移成功,备注等信息保留

## 5. 明确不做

| 不做 | 原因 |
|---|---|
| 多币种 / 汇率 | 已确认完全不做,不留字段 |
| AA 垫付结算(谁该还谁) | 家庭出游通常一个钱包,算法与 UI 成本高、价值低 |
| 反查最优组合(给定预算自动推荐) | 组合求解,复杂度与价值不成正比 |
| 折腾程度量化评分 | 已确认不做 |
| 地图 / 坐标 / 路线规划 | 离线无底图 |
| 跨旅行对比(今年 vs 去年) | 超出单文件模型 |
| 逐小时行程排程、拖拽排序 | 不服务于"算钱"这个核心 |
| 实时抓取携程/飞猪价格 | 违反离线前提,且无公开接口 |

## 7. 术语(用日常语言,不用代码语言)

| 说法 | 含义 |
|---|---|
| 候选 | 某天(或某几天)的某个东西的价格,例如「9/29 合肥~海口 700」 |
| 计划 / 当前组合 | 我此刻正在挑的这一套选择 |
| 方案 | 存下来的具名组合,用于对比;可存多套 |
| 已选 | 我挑中的候选;只有已选的才计入金额 |
| 未定价 | 知道要花这笔钱,但还没查到具体价格 |
| 票档 | 成人 / 儿童 / 老人 等,决定单价 |
| 票档计价 | 同一物品按不同票档给不同价 |
| 套餐 | 必须整段使用的住宿报价(如 3 晚连住 1200) |

**注意:全文不出现「方案层」「数据模型」「字段」「schema」等实现词汇** —— 那些属于 §10。

## 8. 需求验收总清单

不用任何技术术语,只描述用户视角:

**录入**
1. 把现有 Excel 备选表内容录进来不需要重复劳动
2. 一条交通能同时录多个日期的不同价
3. 一条 3 晚套餐录一次,占用 3 天
4. 返利输入后总额确实减少,不是只写在备注里
5. 候选说明性备注只需一列

**选择**
6. 所有候选同时可见,能直接并排比较
7. 同一酒店两个房型并排,能看出每晚差价
8. 一天能放 3 段交通,合计正确
9. 一晚两家不同酒店 → 明确冲突提示
10. 一晚同店两个房型 → 正常相加
11. 套餐占用的晚数,再加单夜房时有提示
12. 空白格子不报错、不计费、不影响保存

**计算**
13. 4 人 3 成人 1 儿童,机票儿童价五折正确;改绝对额也正确
14. 改人数,所有按人计价项同步变化
15. 3 人分 100 元 → 34+33+33,严格 100
16. 有 1 项未定价 → 显示"含 1 项待估",该组合不判为最便宜

**汇总**
17. 日小计相加 === 分类小计相加 === 总费用
18. 各人应付相加 === 总费用
19. 人均 / 日均计算正确

**对比**
20. 存 3 套方案可横向看到类别金额与总价差额
21. 最低价高亮;含未定价或冲突的不参与评比
22. 天数不同的两套能公平比较(人均/日均)
23. 能说出"贵 1240,主要贵在住宿 900"

**记账**
24. 记一笔实付后待付正确
25. 预算 5000 实付 4800 返利 200 → 净支出 4600

**分享**
26. 文件转发后对方双击能看
27. 文字行程单粘微信分段正确
28. 打印预览无控件、分页合理

**数据安全**
29. 10 天缩到 6 天再改回 10 天 → 数据全在
30. 关闭重开 → 未保存编辑可恢复
31. 两副本分别改后写回 → 冲突提示,不静默覆盖
32. 老版本文件自动迁移,信息保留

| 曾经的错误理解 | 正确结论 |
|---|---|
| "少去一人"是独立功能 | 不是。人员在总名单上增减;某套方案里不带某人,是名单的自然延伸 |
| 交通是"方案 = 一套进出港策略" | 不是。交通是逐天从候选里挑,一天可多段 |
| 需要有"方案"这一层容器 | 不需要。当前组合直接改,方案只是存档 |
| 日期范围是用户要维护的参数 | 不是。有哪天有数据,就有哪一天 |
| 套餐少住几晚要算折扣 | 不是计价问题。整段占用,不可少住 |
| 跨方案对比需要日期对齐 | 不需要。只比类别合计与人均/日均 |
| 空白格 = 免费 / 漏填 | 都不是。空白 = 该选项未考虑,合法状态 |
| **布局形态是需求** | 不是。用户要的是"所有候选同时可见可比较",怎么排是实现 |
| **项目→类型两层是需求** | 不是。用户要的是"同店不同房型能并排比差价",怎么组织是实现 |
| **demo 的写法是需求依据** | 不是。demo 是用户用有限手段表达需求的方式 |
