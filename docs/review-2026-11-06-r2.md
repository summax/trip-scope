## 二、新引入的问题(修复的副作用)

### N1【中高】旧的未保存草稿彻底无法访问 —— H3 的修复只覆盖"最新一份"

- **实测**:新建「旧旅行」→ 再新建「新旅行」→ 刷新 → 恢复的是**「新旅行」**;「旧旅行」的草稿键 `tripscope:draft:3f379af9-…` **仍在 localStorage 中**,但界面无任何入口可达。
- **实测**:普通旅行界面「检查本地草稿」按钮数量 = **0** —— 该按钮只存在于安全模式(`SafeScreen`),而安全模式只有"文件数据损坏"才进得去。正常的未保存草稿用户永远看不到草稿列表。
- **根因**:`openBlankTool()` 用 `candidates[0]`(按 `savedAt` 倒序取最新一份),其余静默忽略:

```ts
const d = candidates.find((e) => e.node.project.id === BLANK_TOOL_ID) ?? candidates[0]
```

- **叠加问题**:`newTrip()` 仍然**不清空**上一份未保存草稿(`store.ts:299-306` 只 `deleteDraft(BLANK_TOOL_ID)`),所以每点一次「新建旅行」就多攒一条孤儿草稿,直到 localStorage 配额耗尽 —— 而配额耗尽会触发 `storageError` 横幅,用户却不知道是哪些数据占的。
- **影响**:H3 原本的症状是"数据丢了",现在变成"数据还在但拿不到"。对用户是等价的,只是从"丢失"变成"占用配额且不可见"。
- **建议修法**(二选一,推荐 A):
  - **A. 空白工具打开时,若存在多份未保存草稿,弹选择列表**。复用 `SafeScreen` 的列表 UI,显示项目名 + 保存时间,让用户挑;顺带提供「删除」,把配额问题一并解决。
  - **B. 新建旅行时先 flush 再询问**:「当前旅行尚未保存,是否丢弃?」——只有用户确认才 `deleteDraft(oldId)`,否则保留并让下次启动走 A 的选择列表。
  - 无论哪个,**普通界面必须有一个草稿入口**。数据在存储里但没有任何 UI 可达,等于没有。

### N2【中】同步异常仍然静默 —— H2 的修复只覆盖异步路径

- **实测**:干净基线下(`toast` 节点不存在),注入 `setTimeout(() => { throw ... })` → **无任何 toast**;注入事件处理器同步 `throw` → **无任何 toast**。
- **根因**:`window.addEventListener('unhandledrejection', ...)` 只接 **Promise 拒绝**。`setTimeout` 回调里的同步 `throw`、非 Vue 绑定的 DOM 事件处理器里的同步 `throw`,走的是 `window.onerror` / `error` 事件,而 `main.ts` **没有监听 `error` 事件**。
- **影响**:当前代码里 `saveAsCopy` 的 `deepClone` 已在 async 函数内,能被 Promise 链接住,所以 H1 场景确实修好了。但今后任何"在定时器/裸事件里同步抛错"的代码都仍会静默 —— 而 `scheduleDraft` 的 `setTimeout` 正是这类结构。
- **修法**(一行,与现有 `unhandledrejection` 并列):

```ts
window.addEventListener('error', (e) => {
  console.error(e.error ?? e.message)
  surfaceError(e.error ?? e.message)
})
```

### N3【低】恢复类操作的成功提示不区分成败

- `restoreDraft()`(`store.ts:279-286`):`restoreDraftNode(...)` 返回 `{opened:false}` 时,依然无条件 `setToast('已恢复草稿')`。若草稿数据损坏,`openFromJson` 会切到安全模式,而 toast 却说"已恢复草稿"。
- `restoreFromSafe()`(`store.ts:471-481`)同样:无条件提示「已恢复草稿「xxx」」。
- **修法**:按 `opened` 分支提示,失败时不要覆盖 `openFromJson` 已经设置的安全模式说明。

## 五、优先级建议

进业务功能前,建议按此顺序:

1. **N1**(中高)—— 只修 1 项即可:给普通界面一个"未保存草稿"入口,或新建时询问。这是当前唯一还会让用户"数据拿不回来"的路径。

3. **N3**(低)—— 恢复类操作按 `opened` 分支提示。
4. **L1 / L2**(低)—— 顺手补掉,尤其 L2,否则下次改节点正则还会漏同步。
